## Project Overview

This project builds a complete **Spam Detection pipeline**:

- Downloads and cleans the **UCI SMS Spam Collection** dataset (5,572 messages)
- Preprocesses text: lowercase → strip symbols → remove stopwords → stem
- Converts text to numerical features using **TF-IDF** (top 5,000 features + bigrams)
- Trains a **Multinomial Naive Bayes** classifier
- Achieves **~97-98% accuracy** with high precision and recall on spam
- Saves model artefacts with **Pickle**
- Serves predictions through a **Flask REST API** with a polished dark-mode UI

## How It Works

### 1. Data Preprocessing
Each raw message goes through this pipeline:

```
"WINNER!! Call 09061 to claim £900 prize!"
   ↓  lowercase
"winner!! call 09061 to claim £900 prize!"
   ↓  remove non-alpha
"winner call  to claim  prize"
   ↓  remove stopwords & short words
"winner call claim prize"
   ↓  stemming (PorterStemmer)
"winner call claim prize"   ← root forms
```

### 2. TF-IDF Vectorisation
Converts text into a numerical matrix where each cell represents how
important a word is to a particular message, relative to the whole corpus.

### 3. Multinomial Naive Bayes
Uses Bayes' theorem to compute:
```
P(Spam | message) ∝ P(Spam) × ∏ P(word_i | Spam)
```
The class with the higher posterior probability wins.

```bash
git clone https://github.com/<your-username>/spam-classifier.git

```

### Step 2 — Create a virtual environment (recommended)
```bash

python -m venv venv
venv\Scripts\activate

python3 -m venv venv
source venv/bin/activate
```

### Step 3 — Install dependencies
```bash
pip install -r requirements.txt
```

### Step 4 — Download the dataset
1. Go to: https://www.kaggle.com/datasets/uciml/sms-spam-collection-dataset
2. Download **spam.csv** and place it in the project root directory.

   **OR** use the UCI direct link:
   ```bash
   # Linux / macOS
   curl -L "https://archive.ics.uci.edu/ml/machine-learning-databases/00228/smsspamcollection.zip" \
        -o smsspam.zip && unzip smsspam.zip
   # Then rename "SMSSpamCollection" to spam.csv and ensure it's tab-separated
   ```

## Interview Q&A

**Q1: Why Multinomial Naive Bayes for text classification?**
> Naive Bayes works extremely well for text because it's computationally
> efficient, performs well even with small datasets, and the "bag-of-words"
> independence assumption—while technically wrong—works surprisingly well
> in practice for spam detection. It also has a natural probabilistic
> interpretation.

**Q2: What is TF-IDF and why is it better than simple word counts?**
> TF-IDF stands for Term Frequency–Inverse Document Frequency. Simple
> word counts give high weight to common words like "the" or "is" that
> appear in every document and carry no signal. TF-IDF balances term
> frequency (how often a word appears in *this* message) against inverse
> document frequency (how rare the word is across *all* messages), so
> distinctive words like "winner" or "prize" get high scores in spam.

**Q3: What is the difference between Precision and Recall? Which matters more here?**
> Precision = TP / (TP + FP) — of all messages I labelled spam, how many
> actually were spam? Recall = TP / (TP + FN) — of all actual spam, how
> many did I catch?
> In spam detection, **Recall** is usually more important because missing
> real spam (false negative) is annoying, but flagging a legitimate
> message as spam (false positive, low Precision) is much worse—you could
> miss an important email.

**Q4: Why did you use stratify=y in train_test_split?**
> The dataset is imbalanced (~87 % ham, ~13 % spam). Without stratification,
> by chance the test set could have a very different spam ratio, making
> evaluation unreliable. `stratify=y` ensures both train and test sets
> preserve the original class proportions.

**Q5: What is Laplace (additive) smoothing in Naive Bayes?**
> If a word appears in the test set but never appeared in the training set
> for a given class, its probability would be zero, making the entire
> product zero (since we multiply probabilities). Laplace smoothing adds
> a small constant (alpha=0.1 here) to every word count, ensuring no
> probability is ever exactly zero.

**Q6: How would you improve this model?**
> 1. Use BERT/DistilBERT for contextual understanding.
> 2. Engineer new features: message length, special character density,
>    URL count, ALL-CAPS ratio.
> 3. Try ensemble methods: Random Forest or Gradient Boosting on TF-IDF.
> 4. Use cross-validation instead of a single train/test split for more
>    robust evaluation.
> 5. Collect more labelled data and implement active learning.
